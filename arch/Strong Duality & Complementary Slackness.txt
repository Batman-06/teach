===========================================================================
LP STRONG DUALITY & COMPLEMENTARY SLACKNESS  — explained for an ML person
===========================================================================

Mental model up front
----------------------
If you know Lagrangian duality from SVMs / constrained optimization, you
already know 90% of this. LP duality is just the special case where the
objective and all constraints are linear. The two facts that make the LP case
unusually clean:

  (1) Strong duality holds *unconditionally* whenever the problem is feasible
      and bounded (no constraint qualification to check, unlike general
      nonlinear programs).
  (2) The KKT conditions collapse into a very crisp combinatorial statement
      called complementary slackness.

Everything below builds to one practical payoff: you can CERTIFY that a
candidate solution is optimal without re-solving — the same way you'd verify a
proof is easier than finding it.


---------------------------------------------------------------------------
1. PRIMAL VS DUAL
---------------------------------------------------------------------------

Take a cost-minimization primal in the standard "greater-than" form:

      PRIMAL (P)                         DUAL (D)
      min   c^T x                        max   b^T y
      s.t.  A x >= b                     s.t.  A^T y <= c
            x >= 0                              y >= 0

  - x in R^n  : the decision variables (how much of each activity).
  - c in R^n  : cost per unit of each activity.
  - A x >= b  : m requirement constraints (must meet at least b of something).
  - y in R^m  : the dual variables, ONE PER PRIMAL CONSTRAINT.

Where the dual comes from (the part that makes it click):
Form the Lagrangian by pricing each violated constraint with a multiplier y>=0:

      L(x, y) = c^T x + y^T (b - A x)
              = y^T b + (c - A^T y)^T x

Minimizing over x >= 0: if any coefficient (c - A^T y)_j < 0, you can push that
x_j -> +inf and L -> -inf. So to get a useful (finite) lower bound you must
require c - A^T y >= 0, i.e. A^T y <= c. Under that restriction the x-term
vanishes at the optimum and the bound is just b^T y. Maximizing that bound over
all feasible prices y gives exactly the dual (D).

So the dual is not a trick — it is "find the tightest lower bound on the primal
that you can certify using a nonnegative price on each constraint."

Rule of thumb for the correspondence (memorize this, it kills interview traps):
  - primal CONSTRAINTS  <-> dual VARIABLES   (m constraints -> m dual vars)
  - primal VARIABLES    <-> dual CONSTRAINTS (n vars -> n dual constraints)
  - min <-> max
  - a ">=" primal constraint  -> a ">= 0" dual variable
  - a "<=" dual constraint     comes from an "x >= 0" primal variable


---------------------------------------------------------------------------
2. WEAK DUALITY  (always true, for free)
---------------------------------------------------------------------------

For ANY primal-feasible x and ANY dual-feasible y:

      b^T y  <=  (A x)^T y = x^T (A^T y)  <=  c^T x

Read left to right:
  - b <= A x    (primal feasibility) and y >= 0   =>   b^T y <= (Ax)^T y
  - A^T y <= c  (dual feasibility)  and x >= 0    =>   x^T(A^T y) <= c^T x

Therefore:   dual objective  <=  primal objective,   ALWAYS.

Consequences you get for nothing:
  - Every dual-feasible y is a certified LOWER BOUND on the min cost.
  - Every primal-feasible x is a certified UPPER BOUND.
  - If you ever find x and y with c^T x = b^T y, BOTH are optimal. Done. No need
    to prove it further — weak duality squeezes them together.
  - If primal is unbounded (-inf), the dual must be INFEASIBLE, and vice versa.

The quantity  c^T x - b^T y >= 0  is the DUALITY GAP. In LP it closes to zero.


---------------------------------------------------------------------------
3. STRONG DUALITY  (the LP gift)
---------------------------------------------------------------------------

STRONG DUALITY: If the primal has a finite optimum, then the dual also has a
finite optimum and the two optimal values are EQUAL:

      min c^T x  =  max b^T y       (gap = 0)

Why this is a big deal vs. general optimization:
  - In generic nonlinear / nonconvex problems there is usually a NONZERO gap.
  - In convex problems you get strong duality only under a constraint
    qualification (e.g. Slater's condition — a strictly feasible point).
  - In LP you need NOTHING extra. Feasible + bounded => gap is exactly zero.
    (Provable via the Simplex termination or via Farkas' lemma / separating
    hyperplanes.)

The four possible states (another trap-killer):
      primal \ dual   dual feasible        dual infeasible
      primal feas.    both optimal,         primal UNBOUNDED
                      equal values
      primal infeas.  dual UNBOUNDED        both infeasible (can happen)

Note the asymmetry people forget: "primal infeasible" does NOT force "dual
infeasible" — the dual may instead be unbounded.


---------------------------------------------------------------------------
4. ECONOMIC READING: THE DUAL AS MARGINAL PRICES (shadow prices)
---------------------------------------------------------------------------

This is the interpretation that makes duality intuitive and is exactly how
you'll use it in a real optimizer (and in your DynamoDB/LP energy pipeline).

Each dual variable y_i is the SHADOW PRICE of primal constraint i:

      y_i*  =  d(optimal cost) / d(b_i)

i.e. "if I relax requirement i by one unit, how much does my optimal cost
change?" It is the marginal value of that resource/requirement at the optimum.

Reading it as prices:
  - Constraint i says "produce at least b_i of good i." y_i is what one more
    unit of that requirement costs you at the margin.
  - Dual feasibility  A^T y <= c  reads: "the imputed value of the inputs that
    go into activity j (that's (A^T y)_j) must not exceed its actual cost c_j."
    An activity is only worth running if its priced-out value fully uses up its
    cost — no free profit, a no-arbitrage condition.
  - Strong duality  c^T x = b^T y  is an accounting identity: total cost =
    total value imputed to the requirements. The whole cost is exactly
    explained by the shadow prices on the requirements you were forced to meet.

Caveats to state out loud (interviewers probe this):
  - Shadow prices are LOCAL derivatives, valid only within the range where the
    optimal BASIS doesn't change. Push b_i far enough and y_i jumps.
  - If the LP is degenerate, the shadow price may be one-sided / non-unique
    (left derivative != right derivative).


---------------------------------------------------------------------------
5. COMPLEMENTARY SLACKNESS  (the certificate mechanism)
---------------------------------------------------------------------------

Strong duality forces the two weak-duality inequalities in section 2 to hold
with EQUALITY at the optimum. Equality in a sum of nonnegative terms means
every term is individually zero. That gives the two CS conditions:

  (CS-1)  For each primal variable j:
            x_j * (c_j - (A^T y)_j) = 0
          => either x_j = 0, OR the j-th dual constraint is tight (= c_j).

  (CS-2)  For each primal constraint i:
            y_i * ((A x)_i - b_i) = 0
          => either y_i = 0, OR the i-th primal constraint is tight (A x = b_i).

Plain-English dictionary:
  - "A constraint has SLACK" = it holds with strict inequality (not binding).
  - "A variable is ACTIVE"   = it is strictly positive.

Then CS says, in both directions:

  * If a primal CONSTRAINT is slack (over-satisfied, Ax_i > b_i),
        its price must be ZERO (y_i = 0).
        -> Economic sense: you have surplus of resource i, so one more unit is
           worthless at the margin. Free goods are priced at zero.

  * If a dual PRICE is positive (y_i > 0),
        the constraint must be TIGHT (Ax_i = b_i).
        -> Only scarce (binding) resources carry a positive price.

  * If an activity is USED (x_j > 0),
        its dual constraint is tight: priced value equals cost, (A^T y)_j = c_j.
        -> You only run activities that exactly break even under the prices.

  * If an activity is OVERPRICED ((A^T y)_j < c_j, i.e. dual constraint slack),
        it is NOT used (x_j = 0).
        -> Reduced cost is positive, so it's not worth running.

The term (c_j - (A^T y)_j) is literally the REDUCED COST of x_j — the same
reduced cost the Simplex method watches. CS = "no used variable has nonzero
reduced cost, and no slack constraint has a nonzero price."


---------------------------------------------------------------------------
6. VERIFYING OPTIMALITY WITHOUT RE-SOLVING
---------------------------------------------------------------------------

This is the practical punchline. To CERTIFY that a given x* is optimal you do
NOT re-run the solver. You exhibit a y* and check three cheap things:

   (a) PRIMAL FEASIBILITY:  A x* >= b,  x* >= 0.
   (b) DUAL FEASIBILITY:     A^T y* <= c,  y* >= 0.
   (c) COMPLEMENTARY SLACKNESS: CS-1 and CS-2 hold for every j and i
       (equivalently: duality gap c^T x* - b^T y* = 0).

If all three pass, x* and y* are a matched optimal pair — this is a PROOF, by
weak+strong duality, not a heuristic. Verifying is O(mn) matrix-vector checks;
solving is far more expensive. This is the LP analogue of "checking a witness is
cheaper than finding one."

How you actually get y* to check with: in practice the solver hands it to you.
Any LP/MIP solver (the "dual values", "shadow prices", or "pi" vector) returns
y* alongside x*. CS is then your sanity check that the solver's x* and y* are
mutually consistent.


---------------------------------------------------------------------------
7. WORKED EXAMPLE  (cost minimization, dual solved by hand)
---------------------------------------------------------------------------

A tiny diet/blend problem. Two foods, two nutrient requirements.

  Decision: x1, x2 >= 0  (servings of food 1 and food 2)
  Costs:    c = (2, 3)
  Requirements (A x >= b):
        nutrient 1:   x1 + x2 >= 4      (row 1, dual var y1)
        nutrient 2:   x1 + 3 x2 >= 6    (row 2, dual var y2)

PRIMAL:
      min  2 x1 + 3 x2
      s.t. x1 +   x2 >= 4
           x1 + 3 x2 >= 6
           x1, x2 >= 0

Guess the solution geometrically: the two requirement lines intersect where
      x1 + x2 = 4  and  x1 + 3 x2 = 6
   => subtract: 2 x2 = 2 => x2 = 1, x1 = 3.
   Candidate x* = (3, 1), cost = 2*3 + 3*1 = 9. Both constraints tight here.

Now the DUAL. Using the recipe (2 constraints -> 2 dual vars; 2 primal vars ->
2 dual constraints; min->max; A^T):

      max  4 y1 + 6 y2
      s.t. y1 +   y2 <= 2        (from x1's column: coeffs 1,1 ; cost 2)
           y1 + 3 y2 <= 3        (from x2's column: coeffs 1,3 ; cost 3)
           y1, y2 >= 0

Solve the dual by hand. Because x* used BOTH foods (x1>0 and x2>0), CS-1 says
BOTH dual constraints are tight:
      y1 +   y2 = 2
      y1 + 3 y2 = 3
   => subtract: 2 y2 = 1 => y2 = 0.5, y1 = 1.5.
   Dual objective = 4*(1.5) + 6*(0.5) = 6 + 3 = 9.   <-- equals primal cost 9.

Check everything:
  - Dual feasibility: y >= 0 (yes: 1.5, 0.5);  constraints hold with equality.
  - Strong duality: primal 9 == dual 9. Gap zero. Both optimal. CERTIFIED.

Shadow-price reading:
  - y1 = 1.5: one extra unit of nutrient-1 requirement raises cost by ~1.5.
  - y2 = 0.5: one extra unit of nutrient-2 requirement raises cost by ~0.5.
  (Valid locally, while the optimal basis — "use both foods" — stays optimal.)

A contrasting case to build intuition — what if a constraint were slack?
Suppose requirement 2 had been x1 + 3x2 >= 2 instead. Then at the nutrient-1
optimum you'd over-satisfy nutrient 2 (slack), and CS-2 forces y2 = 0: a
nutrient you have in surplus has zero marginal price.

8. USING SLACKNESS TO SANITY-CHECK A SOLVER'S OUTPUT
---------------------------------------------------------------------------

A concrete checklist when a solver (scipy.linprog, HiGHS, Gurobi, OR-Tools,
PuLP...) hands you x* and the dual/shadow-price vector y*:

  1. Recompute primal feasibility: A x* >= b and x* >= 0 (within tolerance).
  2. Recompute dual feasibility: A^T y* <= c and y* >= 0.
  3. Compare objectives: |c^T x* - b^T y*| ~ 0. A nonzero gap means something
     is wrong (not converged, wrong sign convention, or you grabbed the wrong
     dual vector).
  4. Walk complementary slackness, variable by variable:
        - For every CONSTRAINT with slack (A x* strictly > b): assert y_i ~ 0.
          If the solver reports a positive shadow price on a non-binding
          constraint, that's a red flag / sign-convention bug.
        - For every ACTIVE variable (x_j > 0): assert reduced cost
          c_j - (A^T y*)_j ~ 0.
        - For every variable with positive reduced cost: assert x_j ~ 0.
  5. If using a MIP/heuristic (like your Optuna path), you do NOT get a valid
     dual directly, but you can still use the LP RELAXATION's dual as a lower
     bound: heuristic_cost - LP_dual_bound is a certified optimality GAP for the
     heuristic. This is exactly the right tool to quantify "how far off is the
     fast heuristic from the LP optimum" in your pipeline's deviation check.

Practical gotchas that make checks "fail" spuriously:
  - SIGN CONVENTIONS. Solvers differ on the sign of duals for <= vs >= vs max
    vs min. Always confirm the convention before asserting y >= 0.
  - TOLERANCES. Use relative + absolute tolerances; never test exact equality on
    floats.
  - DEGENERACY. Duals may be non-unique; CS still holds but a particular y* you
    expected might not be the one returned.

9. THREE COMMON INTERVIEW TRAPS
---------------------------------------------------------------------------

TRAP 1 — "Strong duality needs a constraint qualification."
  FALSE for LP. Slater / constraint qualifications are needed for general
  convex programs. For LP, feasible + bounded => zero gap, period. If they're
  thinking of general convex optimization, call that out explicitly; the LP case
  is special precisely because it needs nothing.

TRAP 2 — Confusing the two directions of complementary slackness, i.e.
  claiming "constraint is tight => dual variable is positive."
  WRONG direction. Tightness does NOT force y_i > 0 — a binding constraint can
  still have y_i = 0 (this is exactly DEGENERACY). The valid implications are
  the contrapositives:
        y_i > 0      => constraint tight
        slack (>)    => y_i = 0
  You can go "positive price => binding" and "slack => zero price," but NOT
  "binding => positive price." Many candidates state the false converse.

TRAP 3 — Mishandling the primal-infeasible / unbounded relationships.
  People say "primal unbounded <=> dual unbounded." WRONG. The correct facts:
        primal UNBOUNDED  => dual INFEASIBLE   (and the converse direction is
                                               not automatic)
        primal INFEASIBLE => dual is unbounded OR infeasible
  Both-infeasible is a genuine possibility. The clean biconditional is only:
  "an optimum exists for one <=> an optimum exists for the other, with equal
  value." Keep "unbounded" paired with "infeasible," never "unbounded" with
  "unbounded."

(Bonus trap worth having ready: "the shadow price is a global price." No — it's
a local marginal, valid only while the optimal basis is unchanged; it can be
non-unique under degeneracy and one-sided at breakpoints.)
